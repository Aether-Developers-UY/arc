# Anexos, roles y usuarios — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Setlists separados por anexo (con anexo activo en la app), membresía libre a anexos, y rol admin que gestiona usuarios y anexos.

**Architecture:** Backend Laravel: tablas `annexes` + pivote `annex_user`, `users.role`, `setlists.annex_id`; una `SetlistPolicy` que niega con 404 a no miembros; endpoints de anexos y de usuarios (admin). App Flutter: el usuario de sesión trae `role` y `annexes`; un provider de anexo activo (persistido) filtra setlists y fijados; selector en el shell, pantalla "Mis anexos" y sección "Administración".

**Tech Stack:** Laravel 13 / PHP 8.3 (`C:\wamp64\bin\php\php8.3.28\php.exe`), PHPUnit con SQLite en memoria; Flutter 3.44 / Riverpod 3 / Dio / shared_preferences, flutter_test.

**Spec:** `docs/superpowers/specs/2026-11-16-anexos-design.md`

## Global Constraints

- Textos de UI en castellano rioplatense (voseo), como el resto de la app.
- Roles exactos: `'standard'` y `'admin'`; default `'standard'`.
- Anexo inicial de la migración: nombre exacto **"Anexo principal"**.
- Setlist de un anexo del que no sos miembro → **404** (nunca 403) en todas sus rutas.
- Endpoints de administración (anexos CRUD, usuarios) → **403** para no-admin.
- Borrar anexo con setlists → 422, mensaje exacto: "Este anexo tiene setlists; borralos antes."
- Último admin: no se le puede quitar el rol ni borrar (422). Un admin no puede borrarse a sí mismo (422).
- `songs.created_by` y `setlists.created_by` pasan a nullable + `nullOnDelete`.
- Restablecer contraseña (PUT de usuario con `password`) revoca todos los tokens de ese usuario; cambiar nombre/correo/rol no.
- `POST /setlists` sin `annex_id`: usa el primer anexo del usuario por id; sin anexos → 422.
- Fijados: tope de 3 **por anexo**.
- Commits: solo en la rama `working`, push a `origin/working`; nunca tocar main/stage/backup; no commitear `.claude/`.
- Commits terminan con `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Comandos: backend `cd arc-backend && C:/wamp64/bin/php/php8.3.28/php.exe artisan test`; app `cd arc_app && flutter test` y `flutter analyze` (solo los 2 infos preexistentes permitidos).

## Review Focus

1. Salir del anexo activo (o que lo borren) mientras la app está abierta → la app pasa a otro anexo mío o al estado "sin anexos", sin pantalla de error. (Task 5 test `active annex falls back when it is no longer mine`.)
2. Cambiar de anexo activo no debe des-fijar los fijados del otro anexo (hoy un 404 de un fijado lo borra). (Task 7 test `switching annex keeps the other annex pins`.)
3. Rutas anidadas (`/setlists/{id}/songs`, `/reorder`) también deben dar 404 a no miembros, no solo `show`. (Task 2 tests.)
4. Sesión revocada (contraseña restablecida) en medio del uso → la app vuelve al login en el próximo request. (Task 5 test `a 401 logs the user out`.)
5. Admin editándose a sí mismo: quitarse el rol siendo el último admin → 422 con mensaje claro, y la UI lo muestra. (Task 4 test + Task 10 test `shows the server message`.)
